## Identity and data ownership

Scoped composite primary/foreign keys prevent cross-project references. UUIDs are supplied and retained; legacy opaque IDs have explicit source-qualified aliases, with no claim that live legacy rows have been transformed. Record head and history references are deferred within one transaction. An accepted head always names an existing positive revision; later record writers enforce monotonic mutation and emit the immutable payload/event together. Hash checks bind payload bytes. Blob metadata binds durable object keys and digests; actual original/generated bytes belong in O01's backup boundary.

The [source inventory](evidence/c03-source/legacy-schema-inventory.json) pins every table in the current exported source schema. An explicit disposition map will cover each source table: canonical records/aliases, identity/grants, jobs/history, derived retrieval, or preserved migration/archive custody. Live counts, real-data transformation, compatibility and acceptance belong to C11 and the separately gated v0.1.003 handover; synthetic stable-ID/count/digest tests are labelled as such.
