# C04a implementation choices within the accepted plan

The accepted auth-0003 plan and H-D470 gate remain the authority. Add only the trailing principal kind/adopted and grant roles columns plus private membership view/functions. Keep the28-business-table boundary and frozen C04 migration/source/test bytes. Existing principals remain unadopted, with empty roles. The legacy cortex-add-agent mapping and every adoption manifest state owner_or_admin; a lead role alone does not authorize registration.

Registration and adoption use a private control transaction reusing C04 role/binding/resolve primitives. They deliberately change the current project permission generation. Final authority must still resolve the same installation/tenant/project/principal/control tuple with an intact once-only binding; generation may advance only monotonically. Ordinary C04 authorization remains unchanged. No new role or human kind is inferred from permissions.

Immutable identity audit/mapping payloads use existing core.payloads, with references in principal-bound coordination.idempotency receipts. Verifier privileges/policies expand only for those existing resources and inserts in the three existing auth tables. SQL functions derive actor/project from private authority, never caller scope. No new persistent table or edge store is introduced. C06 capture/live admission remains held for these private source writes.

Bearer material is generated privately from32 random bytes, passed to SQL as its exact-wire ASCII SHA256 digest, and returned only after commit. Replays return credential identity without plaintext. Rotation explicitly revokes the old key. A project owner cannot rotate/revoke credentials for a principal with multiple project grants because existing C04 credentials are principal-scoped; that case needs a separately authorized installer/tenant-owner operation. Registration creates a new principal; adoption does not mint or replace existing keys.

The adoption donor pin is private server configuration, outside caller headers/manifest authority. Its exact source bytes and declared released SHA bind the permitted legacy source identities. Tests use an explicitly synthetic pin to prove source behavior; actual released donor adoption remains NOT_RUN until C02 supplies RELEASED pins. Dry run is owner-only, verifies all mappings and returns an exact manifest digest without writes; apply requires that same digest and immutable audit. Existing human conversion is refused.
