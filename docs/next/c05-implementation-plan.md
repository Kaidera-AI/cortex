## Security grill and fixed invariants

The riskiest assumption is that idempotency, a record head and job ownership can be coordinated without committing a partial or cross-principal result. Falsify on real PostgreSQL with simultaneous same-key requests, conflicting body under one key, late rollback, acknowledged-then-lost response, concurrent claims, expired leases, explicit authorized retry/reclaim and cancellation racing completion. All request ports own `authorized(...)` and keep result private until its successful exit. Replays recheck credentials/grants, so revocation still refuses an old receipt. Inputs are bounded and strictly typed; errors expose fixed codes, not SQL, raw keys or dependency text. Payload bytes are preserved verbatim and hashed; no adapter re-encodes unknown module facts.

Already ruled requirements: principal/project/operation/request-bound idempotency; active credential and project grant; no owner/global fallback; read does not write; owner/admin control where required; authoritative synchronous commit; immutable history; monotonic revisions/tombstones/fences; typed core_unavailable. Installation/project/principal boundaries come from C04 Scope only. No cached authority. A port never opens a second unauthenticated/privileged data connection. Row locks linearize same-record/job actions; request-key insertion/conflict resolution occurs inside that same private transaction. Different principals may use the same request key without sharing a receipt.

External effects remain unresolved after an unprovable completion; retry is an explicit bounded state transition with a new attempt/fence, never blind execution. A cancellation marker is durable and checked while holding the same job lock before completion. Same-key retries return the same committed outcome; new conflicting reuse is typed conflict. A stale holder/fence refuses even if a worker name is reused. Actual HTTP cancellation/forwarded error envelopes remain C02/C11 gates; Core state-machine and error fixtures must be fail-capable now.
