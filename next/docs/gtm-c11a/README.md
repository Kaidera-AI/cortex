# C11a source API and capability boundary

This branch is the source-only C11a unit stacked on X01a `27867d85`. It does not install an API listener, qualify released clients, run a signed update or admit any external engine. Main merge and live adoption remain held by H-D471.

`contracts/c11a-consumer-routes.json` pins Cortex **released v0.1.002** and the C01 matrix. Its 87 guarded method/path entries cover 82 operations observed in the released KOS and `cortex-*` survey, nine released OpenKai 0.1.15 production operations (five overlap), and `/metrics`. `load_routes()` checks every entry against the frozen C01 method, path, disposition and observation row, plus the explicit effect and capability mappings. The two arbitrary SQL routes remain retired. Routes without an injected owner handler return typed `capability_unavailable`, never an empty successful body. The source boundary is not a claim that those legacy response shapes are compatible; C11b must run the unchanged released clients against a mounted API on disposable real PostgreSQL.

`ConsumerGateway` is an ASGI adapter with five required ports: Core probe, principal resolution, authoritative permission recheck, capability-state source and health. Core is probed before every non-health route, including unknown paths, metrics and retired routes. PostgreSQL search/graph readiness requires a real model identity, generation, complete freshness cursor and server-side permission recheck. Qdrant, C10 and other unlanded add-ons are explicitly unavailable regardless of a source claim. The injected write handler may return success only through a `C05Committed` result with a matching server idempotency key and a nonempty committed receipt; exceptions, uncommitted receipts and mismatches fail closed. C05's own transaction/idempotency and C06 outbox suites remain independent inherited gates. An injected handler is trusted to return `C05Committed` only after its C05 transaction returns; C11b must bind and prove that concrete port end to end.

`bin/cortex` and `cortex_core.cli.__main__` now dispatch `cortex status` through the existing bounded read-only client. The installer supplies `CORTEX_API_URL` explicitly; a missing or non-loopback endpoint is refused by the status client. This source wrapper does not choose a port or mount a listener.

Proofs: `next/tests/c11a` has source/body tests, `next/scripts/mutate_c11a.py` runs source-copy faults with the fixed classifier, and `next/scripts/mutate_c11a_pg.py` checks that the gateway recheck blocks handler invocation after real-PG grant revocation. `next/tests/c11a/run_pg.py` starts only one exact-owned, cached PG18.4/pgvector0.8.2 container after a 35% Mac and VM memory gate, with 2 CPU/1 GiB, loopback ephemeral port, tmpfs and exact-owned cleanup. Its data is synthetic. Raw attempts are retained under the canonical lane-A `evidence/c11a-source` folder. Any changed upstream C04–C07 or consumer pin requires a fresh C11 run on the new exact head.
