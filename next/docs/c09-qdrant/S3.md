# S3 controlled projection source — partial, capability UNAVAILABLE

This child of S2 adds the external-target v2 receipt contract, a controlled C07
sink, C10 reads and an explicit C11 source binding. It does not enable a native
transport, runtime factory, collection provisioning or capability READY.

```
committed Core event + immutable binding
  -> QdrantSink (one retained worker, absolute deadline)
  -> PrivateClient (S2 ownership, custody, HTTP bounds, strict decoder)
  -> full-key insert_only OR full-key/revision/effect update_only
  -> completed result -> exact keyed full-point readback
  -> closed v2 receipt -> Consumer validation -> existing c07_record boundary

C04 request -> c09_state -> scoped engine candidates -> current Core proof
  -> C11 principal recheck -> final current-hit recheck -> response
```

The full key is installation, tenant, project, aggregate, complete model identity,
module, consumer generation and collection generation. The deterministic UUID
is an address; full payload equality and the effect digest detect collisions and
conflicts. Each write replaces the complete vector and payload. Equal revisions
with different effects refuse. Replay and stale events reconcile using a
destination-conditional complete-point no-op, completion and keyed readback.
Ambiguous effects do not produce receipts or Core credit; a later delivery may
reconcile. No ordinary upsert, retry or Core-precheck substitute exists.

`module-consumer-v2.schema.json` describes the closed external receipt grammar.
Its structural acceptance is insufficient: `validate_receipt` checks the exact
binding and event before the existing consumer records the original v2 receipt.
The five-field manifest accepts protocol 2 / sink qdrant only with that explicit
binding. Protocol 1 / sink postgres and its schema remain unchanged.

`QdrantProjection` accepts only the controlled S2 private client and the existing
credentialed `_C04Search`. Core supplies scope, permission, current revisions,
applied proof and freshness. Query results are filtered by every binding field
and tombstone, validated as complete points, and compared with current Core
records. No PostgreSQL search miss is needed. Empty unfiltered engine results
with Core-indexed records are unproved. Projection visibility needs both the
Core applied head and exact engine point. Engine failures are scrubbed as
capability unavailable. C11 status remains unavailable, including healthy probes.
Core indexed/pending counts must remain equal across the engine wait and final
C11 recheck; a response cannot attach later Core counts to an earlier hit set.
The controlled query interprets scores as Cosine similarity; native collection
qualification must prove 768 dimensions and the Cosine metric before binding.

## Core admission remains open

`schema/coordination/c09-external-v2.sql` is an **unmanifested, unexecuted draft**.
PG-C owns the next schema append and compatibility seal. No existing SQL file or
manifest is edited. Without admission, `c09_bind` / `c09_state` do not exist and
the admitted v1 `c07_record` refuses the full v2 receipt. The source therefore
fails closed; durable external applied/stale outcomes are **not proved**.

The draft retains one C07 checkpoint/poison/prefix mechanism: it locks the same
checkpoint, validates v2 against the scoped published event, delegates to the
private v1 recorder and persists the actual observed head in the same transaction.
A stale witness must identify a committed, published same-aggregate successor.
The renamed v1 entry point must be inaccessible to the request role. Core reads
derive indexed/pending counts from current records and those applied heads.

The remaining S3 slice needs PG-C owner admission and copied-database controls:
Python/SQL point-ID equivalence; migration compatibility and ownership/ACL/RLS;
immutable generation binding; direct-v1 bypass refusal; concurrent replay/stale
and poison/contiguous progress; same-transaction rollback; commit visibility;
retained-floor and rebuild refusal. Until those pass, this is a partial source
build. Controlled fakes qualify neither PostgreSQL durability nor Qdrant atomicity.

Native Qdrant version/API semantics, destination atomicity and race behavior,
real custody/delivery, provisioning/indexes/metric, rebuild materialization,
runtime shutdown and end-to-end service authorization remain unbound. A timed-out
uncooperative Python dependency may retain its single daemon worker; overlap is
refused and `close` reports unverified cleanup. No S4/B02/release go is granted.
