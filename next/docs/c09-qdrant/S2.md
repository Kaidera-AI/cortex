# S2 bounded private Qdrant source adapter

Authority: Kai row eb7f1ebf-c721-43df-a952-e59434d89b3d; accepted S1, Cox and Vera reviews dated 2026-10-16. Base: 1d1806e9a421d92238f8dcab0b87a442d4c8bf25. This is the six-hour controlled-source slice, for Hale review. It grants no native, receipt, query, benchmark or release acceptance.

## Contract and reuse

`PrivateClient` is an async context manager, with `probe(deadline=<absolute monotonic time>)` and bounded `aclose`. It shares descriptor/private-delivery admission with the existing inert C09 port, strict JSON decoding with runtime contracts/release codec, and the existing async `resolve_key(ref)` custody callback convention. It owns one HTTPX session and its pending tasks. There is no secret lookup from files/environment, alternate parser, SDK, registration, apply or fallback path.

Both descriptor platform labels (`linux/amd64`, `linux/arm64`) use the same code. Their digests are admitted by the immutable descriptor hash, not inferred from the test host. Every status and successful diagnostic probe remains `state=unavailable`, `module_ready=false`, `core_auth_bound=false`, `native_qualified=false`.

## Admission boundary

The current runtime factory has no qualified Qdrant same-host placement/custody supplier. Consequently this S2 source profile admits **only an explicit exact HTTPX MockTransport**. Default/native/unknown transports refuse before credentials or HTTP. The callback convention is reused, but no production custody service or runtime factory binding is claimed. Literal RFC1918/ULA metadata alone cannot establish same-host placement; a future N1 binding must supply real custody/placement qualification rather than accepting a caller READY/same-host boolean. Cross-host HTTP remains disabled. Fixture success cannot qualify native behavior.

Config is exactly the existing private config: literal RFC1918/ULA address, fixed port 6333, no gRPC/published ports/host networking, non-root, internal network, read-only root, ALL capabilities dropped, no-new-privileges, disabled CORS/cluster/telemetry/remote snapshot recovery. IPv6 zones, public/wildcard/loopback names, extra/coerced fields and equal logical refs refuse. These are admitted source settings, not observed host enforcement.

Resolve reader/writer refs afresh within each probe's total budget, reject missing/equal/invalid actual keys, scrub even credential exceptions of our own ProtocolFailure type. The controlled probe tests reader denial of point writes and writer success. Engine keys confer no Core scope or permission.

## HTTP and ownership bounds

Fixed origin from admitted literal address, closed synthetic routes only. Explicit `trust_env=False`, `follow_redirects=False`, no retries. Eight simultaneous operations and sixteen total owned pending operations, including queueing. Default 2 s connect / 5 s total, reducible by configuration and caller deadline; credentials, queue, body, readback and cleanup consume that same deadline. Every awaited stage is followed by a monotonic check, including a synchronous callback which stalls the event loop. Async cancellation cannot force an arbitrary dependency to stop: uncooperative jobs remain owned/counted, the client refuses new probes, and close reports cleanup unverified within its own bounded wait. There is no claim of hard preemption for blocking Python callbacks.

At most 1 MiB serialized request / streamed response; JSON media type, identity encoding, existing strict duplicate/depth/type/finite-value decoder. Response bodies close on refusal/cancellation. Non-200/expected reader-403, malformed, incomplete and ambiguous results are scrubbed `capability_unavailable`. Diagnostics do not expose remote exception text or key material.

## Controlled probe sequence

Check exact pinned runtime version; create a unique disposable collection (768 Dot); verify reader-write refusal; insert a complete synthetic point with `insert_only`; verify filtered `update_only` miss leaves the point intact; verify `insert_only` cannot replace an existing point and `update_only` cannot insert a missing point; then verify matching conditional replacement. Each writer operation uses `wait=true`, `ordering=strong`, completed integer operation result and exact typed vector/payload readback. Every point write has an explicit conditional mode. A cleanup DELETE is attempted once after any possible collection effect, under the original deadline. Cleanup failure is unavailable/unverified; ambiguous writes are not retried. This is a sequential API witness, not atomicity or full-key external receipt proof.
