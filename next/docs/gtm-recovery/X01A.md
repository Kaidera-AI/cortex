# X01a recovery fixture boundary

`cortex_core.recovery_fixture` is an inert controller library. It starts no host,
container, PostgreSQL server or restore. X01b must bind it to the admitted
Production Linux and Standalone macOS packages and execute only after Kai's
separate host GO. The generated Podman command vectors are a dry-run contract,
not evidence that either edition recovered.

The deterministic `synthetic_fixture(seed)` contains two tenants with records,
vectors, blobs, a model identity, schema ledger and consumer checkpoints. Its
bytes derive solely from the seed; it has no path to customer data.

`capture_write` calls the edition client before it timestamps or appends an ACK.
The client must return a server-confirmed `committed` receipt matching the
request ID, record, revision, payload digest and tombstone. A timeout or lost
connection is recorded in `ambiguous.jsonl`, never in `acks.jsonl`. X01b must
resolve ambiguous request IDs through Core's idempotency/read path before
scoring recovery. The controller's ledger directory must be outside all
faulted primary, archive and recovery volumes. Each append is locked and
fsynced; entries form a SHA-256 chain. Record the full-file SHA-256 outside
the fault domain immediately before each injection, since a hash chain alone
cannot detect clean truncation of its tail.

`reconcile` requires the recovered committed receipts to equal a maximal
contiguous prefix of the external ACKs. Altered, unexplained, duplicate or
out-of-order recovered receipts refuse. It reports the lost ACK IDs, the
fault-to-last-recovered-ACK interval, and detection-to-healthy-read-and-write
interval against one edition's numeric limits. X01b also compares authoritative
record, vector, blob, schema, model and checkpoint state to the O01b snapshot;
the ledger alone cannot prove those tables are complete.

`native_restore_plan` checks the host edition/architecture, immutable image
digest, distinct task-owned source/archive/recovery resources and bounded CPU
and memory. Its command vectors specify PostgreSQL's native `pg_verifybackup`
with archived WAL, a network-none recovery container and `pg_ctl` status.
X01b must authenticate/decrypt and stage the O01b base/WAL/blob set, write
recovery configuration and start the correct signed edition target before
these command vectors can be executed. `fault_plan` only describes primary,
owned storage and synthetic logical faults, and requires the logical target
record to belong to the supplied synthetic fixture; it has no executor.
No command or fault plan is proof of a completed restore.

The RED-first controls and source-copy mutations are in
`next/tests/recovery_fixture/` and `next/scripts/mutate_recovery_fixture.py`.
X01b owns native dual-edition timed receipts, resource inventory, external ACK
reconciliation, exact-owned cleanup and the 60/300-second RPO and 30-minute
RTO judgments.
